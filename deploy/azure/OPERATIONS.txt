Frontend hosting
  The production frontend and API run together on the existing Azure VM.
  Dockerfile builds the React frontend and copies its output into the application
  image. Nginx provides HTTPS and proxies to the application on localhost:8000.
  The website and /api use the same HTTPS origin; no CORS configuration is needed.
  PUBLIC_ORIGIN must remain the website's HTTPS origin.
  Vercel hosting is optional and is not used by the production VM deployment.

Optional separate frontend on Vercel
  1. Deploy the current frontend directory, including vercel.json. If importing
     from GitHub, first commit/push the frontend changes and vercel.json.
  2. Set Root Directory to frontend, framework to Vite, build command to
     npm run build, and output directory to dist.
  3. No frontend API-key variables or VITE_API_URL are needed. /api and /health
     requests are proxied to Azure by vercel.json. Shared links use the SPA route.
  4. After Vercel assigns the final production URL, run from the repository:
       powershell -ExecutionPolicy Bypass -File deploy/azure/set-frontend-origin.ps1 -Origin https://YOUR-PROJECT.vercel.app
     Or send that production URL to the assistant to configure it.
     Login writes will be rejected until PUBLIC_ORIGIN matches the Vercel URL.
     A new production domain needs the same update. Preview domains are not
     automatically trusted.
  5. Sign in and use Store management to rebuild the RAG index if needed.

Redeploy the website and backend from this computer
  powershell -ExecutionPolicy Bypass -File deploy/azure/deploy.ps1
  Both the frontend and backend are built from the packaged source. Each release
  has a separate directory and image tag, including the source commit. SQLite stays
  in /opt/storeiq/data and a consistent pre-deployment backup is taken.
  Deployment is serialized with a file lock. Brief downtime occurs when the
  single container is replaced. Health failures fail deployment; automatic
  rollback is not configured.

Backups
  SQLite online backups run daily around 02:30 UTC, including missed runs after
  reboot. The VM identity uploads to the private Blob container without storage
  account keys. Local copies are kept for 7 days, Blob copies for 30 days.

  to a separate SQLite file, and checked for integrity and all three accounts.
  The live database was not overwritten during the restore check.
